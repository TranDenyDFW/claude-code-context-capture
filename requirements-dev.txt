# Development dependencies: everything needed to run the checks, on top of requirements.txt.
#
# Kept separate because the dashboard itself needs none of them. Someone who only wants to LOOK at
# their context does not need a test runner, and someone changing the code should not have to guess
# which of the runtime pins the suite actually depends on.
#
#   pip install -r requirements.txt -r requirements-dev.txt

# The test suite in tests/. One file per tab, each recomputing what the page rendered from SQL it
# writes itself.
pytest>=8.0.0

# The Python linter. Configuration lives in pyproject.toml.
ruff>=0.6.0

# The type checker, over c4x/ only. It was added NON-BLOCKING, because this codebase had never
# been type-checked and a blocking gate on day one would have stopped every other change until an
# unknown backlog cleared. That backlog is cleared and the step BLOCKS; this comment said otherwise
# until an independent review read it.
#
# The floor stays a floor here, deliberately, for the same reason every other line in this file
# does. CI does not install from this range: constraints-ci.txt pins the exact version, which
# matters more for this package than the others, because it is the one whose output can fail the
# job. It was NOT pinned there until that same review found it.
mypy>=1.11.0

# Used by tools/make_constraints.py to compare requirement names PEP 503 style and to check that a
# pin satisfies the floor beside it. It arrived as a transitive of pip and pytest; naming it here
# makes that dependency deliberate rather than something the tool relies on by luck.
packaging>=24.0
